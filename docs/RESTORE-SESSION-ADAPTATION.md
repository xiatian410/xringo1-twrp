# 恢复会话预检与分卷校验

日期：2026-11-11。当前镜像与哈希见[模拟报告](../simulation-report.md)。[0018 补丁](../dtsrc/O1_asic_dual/0018-restore-session-preflight.patch)进入统一设备树的固定补丁序列。本轮没有连接或写入手机。

## 行为修正

恢复现在先生成去重的目标清单，再完成整份清单的预检，最后依次执行恢复。父分区和备份中实际存在的子分区使用同一流程：检查目标是否存在、是否只读、文件名、备份文件类型、分卷结构及校验值；原始镜像还检查实际文件长度与目标容量。后续目标的这些检查失败时，前面的分区也不会先被写入。

- 新恢复会话清除上次已结束备份留下的取消标志；会话内新产生的取消仍会停止流程。
- 未识别的选择项立即失败，不跳过后继续并报告整体成功。重复选择只处理一次；最后一个选择项没有分号也能处理。
- 子分区使用备份目录里识别到的文件名与文件系统，不根据当前文件系统重造名称，也不重复检查父分区的 digest。
- 打开另一备份目录前清空旧文件名、旧选择列表。当前目录没有某个隐式子分区时不继承上次目录的目标；已经识别的文件随后被删除则预检失败。
- 原始镜像容量预检只读打开目标，要求块设备并读取容量。实际写入函数仍会再次验证；普通文件、缺失设备、容量查询失败、超大镜像在预检阶段拒绝。
- 目标总数只计算一次，原始镜像进度预算使用文件真实长度；总字节数溢出会失败。失败和取消不会输出 `restore_completed`，性能状态和临时文件进度会收尾。

`RunRestore` 与 `SetRestoreFiles` 使用现有存储事务锁，防止遵守同一锁的调用在恢复过程中更换文件清单。这不等于所有旧后台线程都已经采用完整会话锁；备份取消线程已由后续[备份会话回放](BACKUP-SESSION-ADAPTATION.md)验证。

## 分卷与 digest

新增 `TwrpDigestDriver::GetBackupFiles()`，供恢复预检、digest 检查和生成共同使用。普通备份要求非空常规文件，拒绝文件符号链接、目录和 FIFO。单文件与同名分卷共存时视为歧义并拒绝。

当前 tar 读取器使用 `线程编号 + 两位分卷编号`，支持线程 0–8：`000/001/...`、`100/101/...` 等。新清单允许不同线程组之间有空档，但要求存在 `000`、每组从 `x00` 开始且组内连续；拒绝读取器不支持的线程编号和数字长度。此前校验循环遇到 `000` 组后第一个缺号就结束，可能漏掉 `100`、`200`。现在检查或生成所有清单内文件的 digest。

禁用 checksum 检查仍会检查文件存在、类型和分卷结构。保留原有缺少 sidecar 的行为：记录 `no_digest` 并继续，不把它声明为校验匹配；已存在但损坏、名称不匹配或内容不匹配的 sidecar 会失败。SHA-256、MD5、大小写十六进制路径均有回放。

仅靠目录无法发现“最后一卷及其 sidecar 都被删除”，也无法得知整组最后一个线程是否缺失。当前没有引入可信的完整备份清单，因此没有宣称分卷完整性问题全部解决。压缩内容损坏、加密密码、tar 成员与恢复文件系统仍由后续读取路径处理。

## 实际生产逻辑回放

[测试驱动](../tests/restore_session_test.py)运行 54 个场景：[结果](../logs/restore-session.json)。保存的修改前源码在同一套夹具上有 45 项失败：[负向对照](../logs/restore-session-before.json)。正常原始镜像、正常父子分区和普通分卷在旧版仍通过，负向对照没有把所有旧行为统一判为失败。

执行范围：

- 实际 `RunRestore`、`RestorePartition`、`SetRestoreFiles`、`CheckBackupCancel` 函数体。
- 实际 `RestoreImage`、`RawReadWrite`、文件系统名称解析函数；普通临时文件通过 fstat/ioctl 边界模拟块设备，读写、同步和文件内容是真实主机 I/O。
- 完整实际 digest driver 与 digest 类，链接本地构建的 BoringSSL；对真实临时文件生成并核对哈希。
- ASan/UBSan；所有夹具固定在带标记的私有 `/tmp/dijun-restore-session-*` 目录，原始镜像打开路径拒绝该目录之外的目标。

覆盖取消残留、未知/重复/无分号选择、子分区不同文件系统、父子独立校验、后续文件缺失/损坏/只读/超大、常规文件/FIFO/符号链接、目录切换、大小溢出、执行中失败/取消，以及跨线程组分卷与 digest 生成。
预检失败用例检查所有目标文件字节未变；执行中失败和取消只检查返回失败与不发布成功，不声称已经写入的数据回滚。

挂载、UI、默认元数据及 file-archive 解压是替身；libbase 的读文件/大小写比较/十六进制辅助函数也是主机替身。BoringSSL 库及头文件、生产源和测试源的指纹保存在报告中。没有在 ARM64 上执行这一测试，也没有执行完整压缩/解密/tar 子进程流程。

## 尚未完成

备份取消线程、tar PID 回收和 `.info` 发布顺序已在[后续 55 项回放](BACKUP-SESSION-ADAPTATION.md)中覆盖。强杀/断电后的整份备份清理、digest 原子发布、完整管理器归档流程与真实进度展示仍待验证；压缩/加密分卷内容另由[管道回放](BACKUP-DATA-PATHS.md#archive-pipeline)覆盖。FlashImage 独立入口的旧取消状态也尚未处理。文件在预检后被外部修改、存储拔出或写入中失败仍可能造成部分恢复；同步内核 I/O 不能由这些检查强制中断。
