## 防止重复工作的规则

1. 开始一项工作先写清：当前缺陷、已有证据、这次动作会改变哪个实现决定。没有可判别的问题时不新建模拟套件。
2. 相同源码、输入和范围的结果直接引用。相关源码改变、新现场失败或明确覆盖缺口才触发重跑；依赖未变时不为刷新日期重跑。
3. 每批汇报分别说明：生产行为改变、仅新增证据、仍缺什么。测试数量和 GitHub CI 通过不等于用户功能修复。
4. 有具体生产缺陷才维护补丁并构建；最终构建继续要求 `installclean` 与 `make -j$(nproc)`。纯文档或证据整理不构建新镜像。
5. 本批只纠正队列和执行规则，没有新增 MTP 修改、测试套件或生产修复。用户关于重复工作的反馈不被解释成取消完整适配目标。
